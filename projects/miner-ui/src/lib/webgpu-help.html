Enable WebGPU

Detect lists one browser adapter when navigator.gpu.requestAdapter() succeeds. This page cannot turn Chrome’s GPU block on. CPU threads still mine without an adapter. Chrome does not publish a supported-adapter catalog; chrome://gpu is this machine.

  1. Open this miner in Google Chrome or Edge on Windows. Cursor’s embedded browser and Chromium inside WSL almost always launch with --disable-gpu.
  2. Visit chrome://gpu (or edge://gpu). Graphics Feature Status should show WebGPU and Gpu compositing as Hardware accelerated.
  3. If Problems Detected says WebGPU is disabled via blocklist or the command line, set chrome://flags/#enable-unsafe-webgpu (WebGPU adapter blocklist) and chrome://flags/#ignore-gpu-blocklist (software-rendering list) to Enabled and relaunch. Linux experimental support also needs chrome://flags/#enable-vulkan.
  4. If Feature Status is Software only, hardware acceleration unavailable, update GPU drivers from NVIDIA, AMD, or Intel (not the CUDA Toolkit), then relaunch and Detect again.
  5. Check chrome://version Command Line. Remove --disable-gpu, --disable-webgpu, --disable-gpu-compositing, or SwiftShader, then relaunch.
  6. Come back here, click Detect GPUs, and tick webgpu:0 before Start.

Chrome’s steps: developer.chrome.com WebGPU troubleshooting.
