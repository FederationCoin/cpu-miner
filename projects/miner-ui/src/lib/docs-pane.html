WebSocket protocol

Newline JSON-RPC. Password x. Path /stratum. Subscribe, authorize, notify, set difficulty, submit. Junk frames are closed. A pool may also send client.pool_stats; a gateway does not. A DATUM Gateway may answer client.pool_info when the operator turns that extra on (default off). The mill only asks on DATUM Gateway WebSocket. At most six WebSocket connections per client IP; one accepted client.pool_info per five seconds on that socket.

If a connection drops or a message times out

The mill reconnects with exponential backoff (1s, doubling to 60s). Hashing continues for 3s, then pauses. Submits retry from an outbox every 8s. Status and a short toast say what happened. Nothing stalls silently.

Pool grades

The app-hosted pool (desktop child process, loopback, JSONL on disk) is for friends, family, LAN, and mesh. One process, no HA, no RDS-style backups. If the process dies or the file is lost, some accepted work can vanish from the TIDES window. With people you know, you can make that right. At scale (strangers, public hashrate, mainnet) it is an incident.

A pro pool needs a shared share store (Postgres), replicas only after that store exists, and backups. Sticky sessions are not TIDES.

DATUM is bring your own node

You speak Stratum v1 to the gateway (or to a Stratum pool). DATUM is the encrypted gateway-to-DATUM Prime Pool link. The mill does not open a DATUM socket. Template construction stays on your federationcoind. Do not send mill hashers to pool WSS /datum.

Pool registration, stake, and attestation

Pool Finder is a public directory, not a login. Listings sit on one side; register on the other. A listing stake is hours of RTX 3090 Ti work, shown as GFCN. You are not sending coin: that balance must sit in the wallet (Electrum Format envelope, attest once per connection). There is no DATUM Prime Pool WebSocket for the mill. The mill talks to a gateway over WSS; the gateway talks to a DATUM Prime Pool over TCP.
